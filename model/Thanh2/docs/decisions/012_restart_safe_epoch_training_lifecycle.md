# Decision 012: Restart-Safe Epoch Training Lifecycle

Date: 2026-08-22
Status: implementation accepted locally; Kaggle checkpoint round-trip pending

## Question

How should long Kaggle runs remain reproducible and recoverable across session
interruptions without allowing Test data to influence training?

## Hypothesis

A deterministic epoch plan plus an identity-guarded atomic checkpoint can
resume at the exact next batch. Validation EER can select checkpoints and drive
early stopping while Test remains isolated until the final locked evaluation.

## Decision

Use one shared single-GPU training lifecycle for ECAPA-TDNN, RawNet3, and
WavLM+MHFA with these invariants:

- Epoch order is a deterministic seed-and-epoch shuffle generated by a private
  RNG. It does not consume global Python, NumPy, or PyTorch RNG state.
- Every utterance is consumed once per epoch; the final partial batch is kept.
- The checkpoint cursor records the exact next batch, global optimizer step,
  and weighted current-epoch loss/accuracy accumulators.
- Training crops continue to derive from seed, epoch, and utterance ID.
- DataLoader workers are recreated each epoch with `persistent_workers=False`.
  A private DataLoader generator prevents iterator construction from changing
  model dropout/layerdrop RNG state.
- FP16 uses a GradScaler initialized at `1024`; finite embeddings, loss, and
  pre-clipping gradient norm are mandatory. Scale backoff fails closed.
- Checkpoints save adapter, target head, optimizer, scaler, cursor, history,
  Python RNG, CPU torch RNG, and active CUDA-device RNG.
- Checkpoint files are written to a sibling partial file, flushed with
  `fsync`, and promoted with atomic `os.replace`.
- Resume uses `torch.load(..., weights_only=True)` and requires an exact match
  of model, dataset, resolved-config hash, manifest hash, seed, and optimizer
  group order.
- A readable JSON sidecar records checkpoint SHA-256, run identity, cursor,
  history, and optimizer groups. Checkpoint binaries remain outside Git.
- Validation callbacks must return finite EER and minDCF. Best-model selection
  uses Validation EER first and Validation minDCF as the documented tie-breaker.
- Early-stopping patience and minimum EER improvement are explicit run
  settings. No final value is selected in this decision.
- Every metric is written to local JSONL. Optional W&B logging uses an explicit
  run ID and `resume="must"` after interruption, preventing duplicate runs.
- Test metrics and thresholds are not accepted by the training engine.

## Evidence

- The dependency-free lifecycle, logging contract, Kaggle-only checkpoint
  implementation, and shared epoch engine are implemented under
  `src/speaker_recognition/training/`.
- The full local regression suite passes `166` tests.
- Tests prove deterministic epoch membership, exact resume suffixes, weighted
  partial-batch metrics, EER/minDCF selection, patience behavior, finite logs,
  monotonic global steps, and required safe-checkpoint source boundaries.
- Local syntax compilation and source inspection cover the Kaggle-only modules.
- A real CUDA checkpoint save/interruption/restore equivalence test is still
  required before a full training run begins.

## Advantages

- Kaggle interruptions lose at most the configured checkpoint interval.
- Resume cannot silently cross configurations, datasets, manifests, or seeds.
- All architectures share the same lifecycle and metric-selection policy.
- Validation-only selection prevents Test leakage.
- Local JSONL remains available if W&B is temporarily offline.

## Disadvantages

- Atomic replacement protects one checkpoint file but cannot make its JSON
  sidecar update part of the same filesystem transaction; the checkpoint is
  authoritative and the sidecar is inspectable metadata.
- Checkpointing large models periodically adds storage I/O and short stalls.
- The current engine is deliberately single-GPU; it does not yet exploit the
  second T4.
- Scheduler, augmentation, epoch budget, early-stopping constants, and
  validation-crop settings still require predeclared screening experiments.
- GPU tensor and RNG round-trip equivalence is not yet empirical evidence.

## Required Next Gate

On Kaggle, train a small deterministic fixture, save after a non-final batch,
restore into newly constructed model/optimizer/scaler objects, finish the next
step, and compare model/head parameters, optimizer/scaler state, cursor,
metrics, and RNG-dependent outputs against an uninterrupted control run.

The executable protocol is
`scripts/smoke_test_checkpoint_resume.py`. It uses a small dropout-bearing CUDA
adapter and the production AAM-Softmax head, AdamW, FP16 GradScaler, lifecycle
cursor, and atomic checkpoint functions. It deletes the uninterrupted runtime
objects before constructing and restoring the resumed runtime. Fourteen exact
checks compare the second-step metrics, complete component state hashes,
cursor, checkpoint/sidecar hashes, and dropout-dependent embedding hash. The
downloaded JSON must pass `scripts/validate_checkpoint_resume.py` locally
before the gate status changes to accepted.

### Rejected Kaggle Attempt 1

The first 2026-08-22 gate run stopped during safe restore before producing
evidence. PyTorch `2.10.0+cu128` represents `torch.__version__` as a
`TorchVersion` string subclass. Saving that object introduced a pickle global
that `torch.load(..., weights_only=True)` correctly rejected. The checkpoint
writer now normalizes the version to a built-in `str`. We explicitly rejected
the alternatives of `weights_only=False` and allowlisting `TorchVersion`
because runtime provenance requires only primitive text and does not justify a
broader deserialization boundary. The gate must be rerun; this failure is not
accepted resume evidence.
